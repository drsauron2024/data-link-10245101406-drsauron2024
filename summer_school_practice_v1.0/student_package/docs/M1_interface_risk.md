# M1 接口、通信与风险说明

> TeachingLink 为学校自定义教学协议，仅用于本课程实践，不对应 ASTERIX、ADS-B/Mode-S、Link 16、企业装备协议或任何行业标准。

## 1. 原始接口提供什么数据？

OpenSky 离线快照（`data/raw_states.json`）：顶层为批次时间 `time` 与状态数组 `states`，每条状态向量按固定索引排列，含目标标识 icao24、呼号 callsign、来源国家、位置/最近联系时间、经纬度、气压高度（备用几何高度）、地面状态、地速、航向、垂直速度等字段。课程只使用仓库内离线快照，不访问实时 API。

## 2. 为什么原始数据不是完整态势结果？

- 未经校验筛选：数据中可能混入无可用时间、航向越界等不可接受记录；
- 未按目标合并：同一目标可能有多条不同时刻报告，态势要求"每个目标只保留时间最新的可接受记录"；
- 未规范化：呼号可能带尾空格，时间与高度需要回退决策，派生字段（time_source、alt_type）尚未生成；
- 未经过传输与接收校验：没有 message_valid 等可信性标志，不能直接当作"已确认的现场状态"。

## 3. 为什么发送方需要把内部状态封装成消息？

内部状态是异构结构（字符串、浮点、布尔），直接传输无法保证双方一致解释。封装成固定 41 字节消息后：双方对字节序、位宽、比例因子、偏置、标志位有统一约定；只传输必要字段，空值由有效位表达；帧头（magic/version/message_type/length/seq）与校验和提供帧定位和错误检测能力。

## 4. 为什么接收方要检查长度、类型、校验和与保留位？

- 长度与 message_length：检测截断或帧边界错位；
- magic/version/message_type：防止把无关数据误认为位置状态消息；
- 校验和：检测传输过程中的比特损坏；
- 保留位：规范预留，当前必须为 0，非 0 说明发送端未遵守规范。

校验不通过的帧记入 validation_log 并标记 message_valid=false，不使程序整体崩溃。message_valid 只代表帧通过本规范的格式与校验检查，不代表来源真实性或安全完整性。

## 5. CSV 与 SQLite 分别承担什么角色？

CSV 是必做路径的中间结果与成果交换格式：人类可读、Excel 可查看、跨工具兼容，承载解码记录、航迹、态势、映射与告警等全部结构化成果。SQLite 是选做的持久化路径，提供结构化查询能力；其不可用不影响必做任务，此时降级为纯 CSV 流程。

## 6. 主要工程风险

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 字段缺失（null） | 无法编码必需字段；或把缺失误判为真实零值 | 先读有效位再解释数值；时间回退 last_contact、高度回退几何高度并记录 alt_type；无可用时间则拒绝生成帧 |
| 消息损坏 | 接收端解出错误位置与状态，态势失真 | checksum 校验与完整接收判据；失败帧记入日志并隔离，不影响后续帧 |
| 字节序不一致 | 多字节字段整体解错，静默出错 | 双方约定网络字节序（大端），编解码统一使用大端格式 |
| 量化误差 | 浮点经整数编码后无法完全还原 | 统一量化函数 Q(y)=floor(y+0.5)，编码前检查量程；往返对比误差不超过一个量化单位 |
| 接口延迟 | 数据陈旧，态势偏离现实 | 时间回退保持可用；M5 按批次时间与记录时间差超过 60 秒触发 DATA_DELAYED 告警 |
| 存储失败 | 持久化结果丢失，实验不可复现 | 检查输出目录可写；CSV/SQLite 双路径，SQLite 不可用时降级 CSV |
